# gainlot · 해외주식 양도소득세 계산기

해외주식·ETF를 팔고 매년 5월에 양도소득세를 신고해야 하는 개인 투자자를 위한 정적 웹앱입니다.
증권사 거래내역을 넣으면 선입선출(FIFO)로 취득가를 맞추고, 연도별 과세표준과 예상 세액을 보여 주며,
연말에 팔면 세금이 얼마나 달라지는지 시뮬레이션하고, 신고용 CSV를 만듭니다.

> 이 계산은 참고용 추정치이며 세무·법률·투자 자문이 아닙니다. 실제 신고 전 세무사 또는 국세청 자료로 확인하세요.

## 주요 기능

1. **거래 입력**: 체결일, 종목, 매수·매도, 수량(소수점 가능), 단가(USD), 수수료(USD), 거래 환율(원/달러)을 입력합니다. 거래마다 환율을 따로 넣습니다.
   CSV 붙여넣기·파일 가져오기(헤더 유무와 탭 구분 모두 지원), JSON 백업 내보내기·불러오기를 지원합니다.
   보유 수량을 넘는 매도, 존재하지 않는 날짜, 음수, 0, 지나치게 큰 값, 빈 값은 모두 거부합니다.
2. **연간 요약**: 매도 건별 양도가액, 취득가액, 필요경비, 양도차익을 보여 주고, 각 매도가 어떤 매수 lot을 얼마나 썼는지 펼쳐 볼 수 있습니다.
   연도별로 이익과 손실을 통산하고 기본공제 250만원을 뺀 과세표준과 예상 세액을 계산합니다.
3. **절세 시뮬레이터**: 보유 lot의 현재가(USD)와 현재 환율을 입력하면 미실현 손익을 보여 주고,
   매도 수량을 넣으면 같은 FIFO 규칙으로 올해 세금이 얼마나 줄거나 늘지 계산합니다.
   "남은 공제 한도 활용" 버튼은 공제 여유 안에서 이익을 실현하는 수량을 근사치로 제안합니다.
4. **신고 준비**: 신고 기간(매년 5/1~5/31)까지 D-day, 준비물 체크리스트, 신고용 CSV 내려받기.
5. **신고용 CSV**: 매도 건별 한 행. 열은 `매도일, 종목, 수량, 양도가액(원), 취득가액(원), 필요경비(원), 양도차익(원)`입니다. Excel에서 깨지지 않도록 UTF-8 BOM을 붙입니다.
6. **AI 분석 (선택)**: 올해 상황을 쉬운 한국어로 요약하고, 연말 전 실현 순서를 제안합니다. 자세한 내용은 아래 AI 섹션을 보세요.

## 실행 방법

ES 모듈을 쓰므로 `file://`로 열면 동작하지 않습니다. 정적 서버로 여세요.

```sh
cd gainlot
python3 -m http.server 8101
# 브라우저에서 http://127.0.0.1:8101/ 열기
```

빌드 단계, 외부 스크립트, 외부 폰트, CDN이 없습니다. 시스템 폰트만 씁니다.

## 계산 규칙

모든 세법 상수는 `constants.js`의 `TAX_CONSTANTS`에 모여 있습니다. 세법이 바뀌면 이 객체만 고치면 됩니다.

| 항목 | 현재 설정 | 근거와 확인 상태 |
|---|---|---|
| 적용 연도 | 2026년 귀속 (2027년 5월 신고) | `appliesTo` 라벨로 화면에 표시 |
| 기본공제 | 2,500,000원 (연 1회) | 소득세법 제103조 기억에 근거. 공식 자료로 재확인하지 않음 |
| 세율 | 22% (국외 상장주식 20% + 지방소득세 2%) | 단순 합산 방식으로 입력. 지방소득세를 국세의 10%로 계산해도 같은 22%. 재확인 필요 |
| 3억 원 초과 구간 | 적용하지 않음, 경고만 표시 | 25% 구간이 있다는 기억이 있으나 확인하지 못함. 해당자는 세무사 확인 필요 |
| 신고 기간 | 매년 5/1 ~ 5/31 | 귀속 연도 다음 해 확정신고 기간. `filingWindow` |
| 손실 이월 | 없음 (`lossCarryForward: false`) | 양도 결손금은 다음 해로 넘어가지 않는다고 봅니다. 같은 해 안에서만 통산 |
| 환율 기준 | 거래마다 사용자가 입력한 값 사용 | 거래일 기준과 결제일 기준 중 무엇이 맞는지 세무 판단 필요. **미정** |
| 수수료 | 기본: 필요경비 산입 (`feeAsExpense: true`) | 매수·매도 수수료를 필요경비로 보는 해석. 옵션으로 끌 수 있음. **미정** |
| 같은 날 주문 순서 | 기본: 매수 먼저 (`sameDayBuyFirst: true`) | 체결 시각을 모르면 이 순서를 씁니다. 옵션으로 바꿀 수 있음 |

계산 순서는 다음과 같습니다.

1. **FIFO 매칭**: 종목별로 매수 lot을 날짜와 입력 순서대로 쌓고, 매도 시 가장 오래된 lot부터 소진합니다. 보유 연도와 무관하게 lot은 다음 해로 이어집니다.
2. **매도 건 금액**: 양도가액 = 매도 수량 × 매도 단가(USD) × 매도 환율. 취득가액 = 소진한 lot의 수량 × 매수 단가 × 매수 환율. 필요경비 = 옵션이 켜져 있으면 매수·매도 수수료(원화 환산).
   양도차익 = 양도가액 − 취득가액 − 필요경비.
3. **반올림**: 계산 중에는 소수점을 유지하고, 매도 건 단위로 양도가액, 취득가액, 필요경비를 각각 원 단위로 반올림합니다(0.5는 0에서 멀어지는 쪽). 양도차익은 반올림된 세 값으로 계산하므로 항상 정수입니다. 화면의 lot별 금액은 참고용이며 합계와 1원 차이가 날 수 있습니다.
4. **연간 집계**: 해당 연도 매도 건의 이익 합계와 손실 합계를 구하고 순손익 = 이익 − 손실.
5. **과세표준**: max(0, 순손익 − 2,500,000원).
6. **예상 세액**: 과세표준 × 22%, 원 미만 절사.
7. **공제 여유**: max(0, 2,500,000 − 순손익). 이 금액까지 이익을 실현해도 세금이 0원입니다.

## 테스트

```sh
node --test tests/logic.test.js
```

61개 테스트가 다음을 확인합니다.

- FIFO: 두 lot에 걸친 매도, 부분 체결, 보유 초과 오류, 종목 분리, 같은 날 주문 순서, 소수점 수량, 전량 매도, 환율 차이에 따른 차익
- 수수료: 산입과 비산입, 부분 체결 시 수수료 배분
- 연간: 손익 통산, 전년도 손실 미이월, 공제 경계(정확히 250만원, 1원 초과), 3억 경고
- 반올림: 0.5 경계, 매도 건 단위 반올림, 정수 차익
- 입력 검증: 날짜(존재하지 않는 날짜, 미래, 형식), 숫자(빈 값, NaN, Infinity, 지수 표기, 음수, 0, 소수점 초과, 상한), 티커, 환율 범위
- 시뮬레이터: 가상 매도의 세금 차이, 수수료율 반영, 보유 초과, 공제 여유 제안, 현재가 없는 종목 제외
- 신고 D-day: 신고 기간 전, 중, 지난 뒤
- CSV: BOM과 CRLF, 따옴표와 줄바꿈, 한글 헤더, 탭 구분, 잘못된 행(날짜, 수량 0, 음수 단가, 잘못된 구분, 환율 범위, 열 개수, 숫자 형식), 필수 헤더 누락, 닫히지 않은 따옴표
- 백업: 왕복 복원, 잘못된 JSON, 다른 앱 파일, 잘못된 거래, 보유 초과가 든 백업 거부
- AI: 전송 데이터에 날짜와 거래 ID가 없는지, 요청 본문, 키 형식, 응답 파싱, 제어문자 제거, 길이 제한, 규칙 기반 문장, 네트워크 오류·401·429·시간 초과 처리

브라우저 검증은 Playwright로 390×844와 1280×800, 라이트와 다크에서 실행해 콘솔 오류와 가로 스크롤이 없음을 확인했습니다.

## 데이터와 개인정보

- 모든 데이터는 이 브라우저의 `localStorage`에만 저장됩니다. 서버로 보내지 않습니다.
  - `gainlot-trades`: 거래 목록
  - `gainlot-settings`: 계산 옵션, 마지막 환율, 시뮬레이터 환율과 수수료율
  - `gainlot-prices`: 시뮬레이터의 현재가
  - `gainlot-checklist`: 신고 준비 체크 상태
  - `gainlot-ai-key`: 선택 사항인 Anthropic API 키
- 기기를 바꾸거나 브라우저 데이터를 지우면 사라집니다. 정기적으로 JSON 백업을 받아 두세요.
- 저장소가 막혀 있으면 화면에 알림이 나오고, 변경 내용은 새로고침하면 사라질 수 있습니다.

## AI 분석 섹션

- **선택 사항입니다.** 키가 없어도 같은 레이아웃의 규칙 기반 분석을 볼 수 있습니다.
- 키는 사용자가 직접 입력하고 `localStorage`(`gainlot-ai-key`)에 저장합니다. 브라우저에 저장한 키는 개발자 도구에서 보일 수 있으니 공용 PC에서는 저장하지 마세요.
- 버튼을 누를 때만 `https://api.anthropic.com/v1/messages`로 요청합니다. 모델은 `claude-haiku-5-5`, 응답 토큰은 최대 700입니다. 브라우저에서 직접 호출하며 `anthropic-dangerous-direct-browser-access` 헤더를 씁니다.
- **보내는 데이터**는 화면에 미리보기로 보입니다. 올해 연도 합계(총이익, 총손실, 순손익, 공제, 과세표준, 예상 세액, 공제 여유, 매도 건수), 종목별 보유 수량, 원가, 미실현 손익, 올해 실현 손익, 환율입니다. **날짜, 거래 ID, lot 정보, 계좌 정보는 보내지 않습니다.**
- 응답은 text 블록만 읽고, 제어문자를 지우고, 3,000자로 자릅니다. 화면에는 `textContent`로만 넣습니다.
- 실패하면 오류 메시지와 함께 규칙 기반 분석을 보여 줍니다.

## 한계와 미검증 사항

- **세법 상수는 공식 자료로 다시 확인하지 않았습니다.** 기본공제, 세율, 신고 기간, 손실 이월 규칙은 작성 시점의 기억에 근거합니다. 반드시 `constants.js`와 함께 확인하세요.
- 3억 원 초과 구간의 추가 세율은 적용하지 않습니다.
- 지방소득세의 계산 방식(단순 2% 합산 대 국세의 10%)에 따라 구간별 결과가 달라질 수 있습니다.
- 환율 기준(거래일 대 결제일)과 수수료 처리는 사용자 설정 또는 입력값에 맡깁니다.
- 배당, 이자, 기타 해외 소득과 국내 주식 양도소득은 계산하지 않습니다.
- 주식분할, 액면분할, 배당 재투자, 해외 ETF 분배금, 외화 현금 환차익은 지원하지 않습니다.
- 같은 날 여러 체결의 실제 순서는 알 수 없어 기본 규칙(매수 먼저)을 씁니다.
- 공제 여유 활용 제안은 근사치입니다. 정확한 세금은 시뮬레이터 결과 카드에서 다시 계산합니다.
- 같은 거래를 두 번 입력하면 중복으로 남습니다. CSV 가져오기는 기존 거래와 같은 행을 건너뛰지만, 수동 입력은 막지 않습니다.
- 보유 수량 검증은 입력 순서가 아니라 체결일과 주문 규칙을 기준으로 합니다.
